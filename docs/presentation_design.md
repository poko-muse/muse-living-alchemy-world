# 見せ方の設計（人間に見せる画面の原則）

2026-11-19 Fuu の方針決定に基づく。

## 原則（Fuu）
- 羅列だと見る方が引き込まれない。**パッと見て魅力が伝わり、興味を持ったらより深くハマれる**画面にする。
- サイトは無料で眺める場所。販売は外部（有料note等）という線引きは維持する（docs/monetization_plan.md）。

## 画面の構造（第1段、2026-11-19 実装済み）
1. **ヒーロー**: 世界全景の地図を大きく置き、その上に世界名と「今日」の状態（暦・季節・天気・人口）を重ねる。一目で世界観が伝わることを最優先。
2. **今日のフラスカリア**: 最新の履歴から読者向けイベントだけを物語カードで表示。在庫変動・素材消費などの機械的記録は出さない。錬金実験は特別枠で目立たせる。
3. **図鑑（素材・調合品）**: カードは絵と名前と一言まで。産地・性質・採取条件・価格・使われる調合などの詳細は「くわしく見る」を開くと出る二段構え。
4. **住民名鑑**: カード＋「人となり」（性格・いまの活動・目標・大切な出来事）を開いて読む。
5. **世界の歩み**: 日ごとの日誌。新しい4日分を表示し、それ以前は「もっと古い記録」で開く。失敗も消さない。
6. **この世界について**: 世界の成り立ちと場所の一覧。

実装は engine/generate_site.py（静的HTML、details/summary のみで JS 不要）。日次ワークフローが同じ生成器を使うため、毎朝の自動更新でもこの見せ方が維持される。

## UI参考（2026-11-19 Fuu 提示）
Fuu が「ミニチュア庭園フラスカリア／箱庭ガーデン」のゲーム風UIモック4枚を提示し、この見せ方を目標にすることが決まった。リポジトリに保存： `assets/visual-samples/reference_ui_top_flask.jpg`（トップ画面：フラスコ全景＋素材・レシピ・できることパネル）／`reference_ui_encyclopedia.jpg`（図鑑画面：カテゴリ絞り込み＋アイコングリッド＋右の詳細パネル）／`reference_ui_garden_status.jpg`／`reference_ui_garden_plan.jpg`。
取り入れる要素：
- 木枠＋羊皮紙パネルの「ゲームの図鑑を開いた」フレーム感、リボン風の見出し
- トップはフラスコ全景を主役に、右側へ「集められる素材」「調合レシピの例」「この世界で起きること」をパネルで並べ、一目で世界の魅力が伝わる構成
- 図鑑はグリッド＋詳細パネル方式（選んだ素材が大きく表示され、説明とレシピ材料チップが出る）。スマホでは詳細がカード下に開く形に翻訳する
- 未発見素材はシルエット＋「まだ正体がわかっていない。発見を目指しましょう」で期待感を作る
- 世界の状態は数値・ゲージのパネルで見せる（人口・暦・天気など実データで）
注意：モック内の数値・追加レシピ（癒しのアロマ等）は実在しないダミー。実装は必ず world/*.json の実データだけで行う。

### 器の変更：フラスコから箱庭へ（2026-11-19 Fuu 決定）
丸いフラスコはスマホの四角い画面で小さく見えるため、世界の器自体を「机の上の木枠の箱庭」に変更した。フラスコは「人工の世界」というイメージの源であり、器としては使わないが、世界の理（ことわり）として残す。世界名「フラスカリア」と暦「フラスコ暦」は理の名として据え置き。ガラスが豊富なこととキラキラした質感も、世界の持ち味として維持する（ガラスの天蓋、ガラス細工、結晶の輝き）。
移行は歴史として扱う：フラスコ時代の2日間は消さず、フラスコ暦1年1月3日に「大移し替え」を世界の出来事として記録する。フラスコ版の地図は「第1章の姿」として保管し、地図とキービジュアルは箱庭版を新規に作る。

### 感情の核：机の上の箱庭（2026-11-19 Fuu）
4枚の中で Fuu が最も強く反応したのは1枚目（reference_ui_garden_status.jpg）の「机の上の箱庭」。木箱のミニチュア庭園がランプの灯る机の上に置かれ、手に取れそうな実物感と温かさがある。フラスカリアは「Fuu が見守る小さな世界」であり、観察者の視点をそのまま絵にできるこのモチーフを、見せ方の感情の核とする。トップ画面の主役は、フラスコ全景そのものよりも「机の上に置かれたフラスコ庭園」のキービジュアルが候補。
