## 3. 生成ルール

- **画風参照の添付（必須）**： 毎回 `assets/visual-samples/reference_item_design_sample.jpg` を画風参照として添付して生成する。住民ポートレートでは加えて `reference_poko_workshop.jpg`（体型・場面の基準）も参照する。参照なしの生成はしない（画風ブレ防止）。
- **形式**： 単品（1アイテム／1キャラクター）を中央に大きく、背景は無地のクリーム色。羊皮紙カード・リボン・後光などの「画面装飾」はサイト側で付けるため、生成画像には含めない。
- **文字なし**： 画像内に文字・ロゴ・署名を一切入れない。名前やラベルはサイト側 HTML/CSS で重ねる。
- **プロンプトの型**： 「丸みのある可愛らしい手描きイラスト／柔らかな厚塗り／適度な光沢／手描き感のある輪郭／鮮やかだけれど優しい色／ぽってりしたデフォルメ／神秘性を失わない」を共通指定とし、対象ごとの固有要素（素材なら産地・性質の視覚化、住民なら第1-3節の方向性）を1〜2点だけ足す。パステル・水彩の淡さは禁止（v2修正の教訓）。
- **ファイル命名規則と配置先**（サイト組み込み前提の正式パス）：
  - 素材： `site/assets/items/mat_XXX.webp`（例： `site/assets/items/mat_001.webp`）
  - 調合品： `site/assets/items/rec_XXX.webp`（例： `site/assets/items/rec_002.webp`）
  - 住民： `site/assets/residents/res_XXX.webp`（例： `site/assets/residents/res_001.webp`）
  - 地図： `site/assets/maps/flaskaria_overview.webp`
  - 制作途中の候補・不採用案は `assets/visual-samples/` に残し、正式配置先には採用案のみを置く。
- **形式・サイズ**： WebP、長辺 1024px 程度を目安にし、リポジトリ肥大を避ける（1点 300KB 前後を上限の目安）。

## 4. QA チェックリスト（生成ごとに目視確認）

- [ ] **画風**： 柔らかな厚塗りになっているか／手描き感のある輪郭か／色は「鮮やかだけれど優しい」範囲か（パステルの淡さ・原色のギラつき、どちらにも寄っていないか）
- [ ] **造形**： ぽってりしたデフォルメシルエットか／角が立った硬い造形になっていないか
- [ ] **神秘性**： かわいさだけでなく、錬金術の世界らしい神秘性・素材の魅力（光沢、発光、結晶感など）が残っているか
- [ ] **統一性**： 基準見本・制作済み2点と並べて、同じ世界のアイテムに見えるか
- [ ] **文字混入なし**： 文字・ロゴ・落款ふうの崩れ文字が入っていないか（入っていたら原則再生成。端の小さな崩れは切り取りで除去可能な場合のみ許容）
- [ ] **ポコの短首ルール**（住民バッチ）： 首が短く太く、頭が丸い体にほぼ直接乗っているか／首長竜化していないか／セージグリーン×桃色・角2本が現行アバターと一致するか
- [ ] **未発見素材の扱い**（mat_011）： シルエット＋？に留まり、性質・色・形を断定していないか
- [ ] **データ整合**： 素材の産地・性質と矛盾する描写（例：水属性なのに炎まみれ）がないか
- [ ] 1点につき再生成は原則2回まで。それでも揃わない場合は無理に採用せず、バッチ報告に残件として明記する

## 5. サイト組み込み（計画のみ・本計画書では実装しない）

対象： `engine/generate_site.py`（現在、住民・素材はテキストのみの `<li>` を生成している）。

改修ポイント：
1. **画像差し込み**： 住民名鑑・錬金術図鑑（素材／調合品）の各項目に、ID から引いた画像パス（`assets/items/mat_XXX.webp` 等）の `<img>` を追加する。ファイルが存在しない項目は画像なしで表示する（段階的な組み込みを可能にする）。
2. **図鑑カード化**： 素材・調合品は羊皮紙ふうカード＋セージグリーンの名前リボン（HTML/CSS）を重ね、基準見本の「図鑑画面」の見せ方をサイト側で再現する。
3. **地図の配置**： 地理セクションの先頭に `assets/maps/flaskaria_overview.webp` を置き、地名ラベルは CSS で重ねる。
4. **未発見の表示**： mat_011 はシルエット画像＋「未発見」表記にし、`discovery_status` が discovered に変わったら通常画像・通常表示に切り替える分岐を入れる。
5. **モーションの適用範囲**（CSS/SVG の軽量アニメーションに限定）：
   - 図鑑カード内のアイテム画像： ゆっくりしたふわふわ浮遊（数px の上下動）
   - レア素材（rare 以上）と地図の見どころ： キラキラ粒子の控えめな点滅
   - 名前リボン： ごく小さな揺れ
   - 適用しないもの： 住民ポートレートの常時アニメーション、本文テキスト、動画ファイルの使用（重さ・酔い防止）
6. 組み込み後はサイト生成 → 表示確認までを1バッチの完了条件に含める。

※ 本節は改修方針の記述であり、`generate_site.py` の実装変更は量産開始の合図後に別途行う。

## 6. 開始条件と概算

- **開始条件**： Fuu の「量産開始」の合図があるまで、画像の新規生成は行わない。本計画書の作成・push はその合図には当たらない。
- 開始後はバッチ順（1→6）に進め、各バッチ完了ごとに結果（採用点数・再生成回数・残件）を報告する。
- **概算の生成回数（正直な見立て）**：
  - 残り 21 点 × 初回生成 21 回
  - 再生成の見込み： QA 不合格・画風ブレで、経験上 3〜5 割の点数に 1 回以上の再生成が発生する → +10〜15 回程度
  - 地図は構図の試行錯誤が多く、単独で 3〜4 回を見込む
  - **合計 約 35〜45 回**の生成が現実的な見立て（上限を保証するものではない。再生成が上限に達した点数は残件として報告し、勝手に品質を落として採用しない）
- 費用は発生しない（既存の生成手段の範囲内）。新たな外部サービス登録・公開は行わない。
